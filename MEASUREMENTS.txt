5) COLD START + MEMORY: JIT vs Native AOT (measured, macOS arm64)
================================================================================

Command:
  bash scripts/measure-cold-start.sh

What "cold start" means here:
  Process start → Kernel built with plugins → print STARTUP_MS → READY → exit
  Flag: --startup-benchmark
  5 runs each, after one warm disk run
  Metric: in-process Stopwatch in Program.Main (STARTUP_MS)
  Memory: macOS /usr/bin/time -l  "maximum resident set size" (bytes)

JIT (PublishAot=false, self-contained osx-arm64):
  Publish dir size ≈ 95,236,096 bytes (~90.8 MB)
  STARTUP_AVG_MS   = 99
  STARTUP_MIN_MS   = 97
  STARTUP_MAX_MS   = 101
  MAX_RSS_AVG_MB   = 63.52

Native AOT (PublishAot=true, self-contained osx-arm64):
  Main binary      ≈ 16,203,856 bytes (~15.5 MB)
  Publish dir size ≈ 83,795,968 bytes (~79.9 MB)  [includes macOS dSYM debug bundle]
  STARTUP_AVG_MS   = 48
  STARTUP_MIN_MS   = 47
  STARTUP_MAX_MS   = 50
  MAX_RSS_AVG_MB   = 24.18

dSYM note: The 79.9 MB AOT dir includes an 89 MB macOS .dSYM debug symbol bundle
  which is platform-specific and not shipped in the Linux Docker image.
  Linux AOT binary (from Docker build) = just the stripped binary + appsettings.json.

Derived (from THESE measured averages):
  Cold-start improvement:  (99 - 48) / 99  ≈ 51.5% faster
  RSS reduction:           (63.52 - 24.18) / 63.52 ≈ 61.9% less RAM

Honest LinkedIn/resume wording:
  "Published with .NET Native AOT; on macOS arm64 self-contained builds,
   agent startup averaged 48 ms vs 99 ms JIT (~52% faster), and peak RSS
   averaged ~24 MB vs ~64 MB (~62% less memory). Logged in MEASUREMENTS.txt."

DO NOT say the old invented marketing numbers:
  3.2s → 310ms (90% faster)
  205MB → 82MB (60% smaller)
  Those were NEVER measured on this project. Actual improvement is real but
  more modest: ~52% faster startup, ~62% less peak RAM.
